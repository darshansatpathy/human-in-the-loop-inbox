# Performance

Generated by `python bench/load.py --flows 400 --concurrency 16`: the service against one PostgreSQL, on a two-core machine that was running other jobs at the same time, every request through the full flow (submit, an agent long-polling, a reviewer approving, the executor consuming the grant).

**400 complete approval flows in 9.8 s (41 a second)** with 16 in parallel. Audit chain after the run: 1380 events, intact.

| Step | p50 ms | p95 ms | p99 ms |
|---|---|---|---|
| Submit (policy, insert, audit event) | 77.6 | 116.0 | 181.6 |
| Approve (lock, vote, quorum, grant) | 136.5 | 215.9 | 247.6 |
| Agent's long poll wakes after the vote | 5.4 | 15.8 | 23.3 |
| Executor consumes the grant | 108.0 | 191.2 | 226.4 |
| Whole flow, excluding the 50 ms before the vote | 337.8 | 441.8 | 495.5 |

Every audit event takes a transaction-scoped advisory lock to extend the hash chain, so event appends are serialised; this is the throughput cost of a single tamper-evident chain.
